# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有 Ai路人。
- Ai路人是白色圆润人形、黑色椭圆眼、无嘴无衣服。
- Ai路人在白底中轮廓清楚，没有和背景融在一起。
- Ai路人承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面轻怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 橙色路径连续可读，没有被截断，也没有穿过角色身体、机器实体、卡片或道具。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- Ai路人像吉祥物、表情包、可爱卡通、机器人、宇航员或潮玩。
- Ai路人被画成黑色角色，或加了衣服、嘴、鼻子、头发、鞋子。
- Ai路人多出手、手臂、手指，或一只手同时做多个动作。
- Ai路人的脚、腿、手臂或身体和道具融合、穿插、共用轮廓，或被道具遮到读不清。
- 橙色路径横穿机器内部、角色身体或道具，导致层级混乱。
- 白色角色在白底里看不清。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 出现虚线、点线、工程标注线或草稿辅助线。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有轻怪诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让 Ai路人成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 quiet passerby、deadpan、blank oval eyes、not cute、not mascot。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和 Ai路人动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“这个路人在认真处理一个抽象问题”，然后 1 秒内看懂结构。

如果第一眼像教程页、吉祥物海报或儿童卡通，而不是白纸上的轻怪诞产品草图，就不合格。
